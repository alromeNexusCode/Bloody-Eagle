# 📅 خطة تنظيم المهام - مشروع النسر الدامي

## نظرة عامة
بعد الانتهاء من إضافة الأكواد الأساسية على GitHub، الخطوة التالية المنطقية والأكثر أهمية هي تنظيم المهام وتوزيعها. هذا هو أساس العمل لأي مشروع برمجي كبير.

## نظام إدارة المهام في GitHub

### 📋 1. إنشاء المهام الأساسية (Issues)

سنقوم بإنشاء "قضايا" لكل جزء مطلوب في المرحلة الأولى. هذا يساعد فريقك (أو أنت شخصياً) على تتبع ما يجب بناؤه.

| اسم المهمة (Issue Title) | الوصف المختصر | التعيين (Assignee) |
|---|---|---|
| **Setup 1.1: Project Environment** | إعداد مشروع Unity/Unreal جديد وتهيئة الخادم الأساسي (Backend). | Server/Client Teams |
| **Feature 1.2: Base Building (C1-C15)** | تنفيذ نظام البناء لعرين النسر والمباني الأساسية حتى C15. | Client/Design |
| **Code 1.3: Integrate Unit Balance** | دمج الكود UnitBalance.cs في نظام القتال وتطبيق معاملات +30% و -25%. | Server Team |
| **Code 1.4: Implement Chat Parser** | تطبيق الكود ChatColorParser.cs في نظام الدردشة وتفعيله. | Client Team |
| **Asset 1.5: Core UI Assets** | تصميم الأصول البصرية ولوحة الألوان (Icons) المعتمدة في خطتنا البصرية. | Art Team |

### 📝 2. إنشاء لوحة المشروع (Projects Board)

سنستخدم ميزة Projects في GitHub لإنشاء لوحة "كانبان" (Kanban Board) بسيطة لتتبع تقدم المهام:

| العمود (Column) | المهام التي توضع فيه |
|---|---|
| **To Do (للقيام بها)** | جميع المهام التي تم إنشاؤها للتو (مثل المهام الخمسة أعلاه). |
| **In Progress (قيد التنفيذ)** | المهام التي يعمل عليها الفريق حاليًا. |
| **Done (تم الإنجاز)** | المهام المكتملة (يجب نقلها هنا بعد الانتهاء منها). |
