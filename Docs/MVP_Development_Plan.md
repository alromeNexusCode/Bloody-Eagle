# 🛠️ خطة تطوير النموذج الأولي (MVP Development Plan)

## المرحلة 1: الإعداد الأولي (3-5 أيام)

### 1. إعداد البيئة التقنية
**المطلوب:**
- تثبيت Unity Hub و Unity LTS (آخر إصدار مستقر)
- إنشاء مشروع Unity جديد (3D)
- إنشاء مستودع GitHub جديد
- إعداد MongoDB Atlas لحفظ البيانات

**الملفات المرجعية:** 
- `Setup_1.1_Complete_Issue.md` (دليل الإعداد)

### 2. بناء هيكل المشروع
**في Unity:**
```
Assets/
├── Scripts/
│   ├── Client/          # نسخ ملفات من مجلد Client/
│   ├── UI/              # واجهات المستخدم
│   ├── GameLogic/       # منطق اللعبة
│   └── Data/            # نماذج البيانات
├── Scenes/              # المشاهد (القلعة، القلعة، الخرائط)
├── Prefabs/             # القوالب الجاهزة
└── Resources/           # المصادر البسيطة (خلفيات، أيقونات)
```

### 3. دمج الملفات الأساسية
**أولوية النسخ من مجلد Client/:**
- `PlayerProfileData.cs` ← `Assets/Scripts/Client/`
- `PlayerResources.cs` ← `Assets/Scripts/Client/`
- `ServerManager.cs` ← `Assets/Scripts/Client/`
- `UnitBalance.cs` ← `Assets/Scripts/Client/`

## المرحلة 2: بناء الواجهة الأساسية (5-7 أيام)

### 1. شاشة القلعة الرئيسية
**المصادر المرجعية:**
- `ArtDirection.md` (الطابع المعماري)
- `ArtAssetList.md` (الموارد البصرية)

**الهدف:** عرض بسيط للقلعة مع:
- 3-4 مباني أساسية (قلعة، ذخيرة، سوق، مستشفى)
- شريط موارد في الأعلى
- زر "ملاحة سريع" للانتقال بين المباني

### 2. نظام التنقل
**مكوناته:**
- واجهة تلوّن المباني عند الضغط عليها
- قائمة منبثقة "تطوير/بناء" لكل مبنى
- عرض التكلفة في الموارد (من ملف `BuildingCosts.md`)

## المرحلة 3: اختبار القتال (5-7 أيام)

### 1. إعداد خادم Python
**الملفات المرجعية:**
- `MinimaxLogic.py` (خوارزمية AI)
- `app.py` (Flask server)

**المطلوب:**
- تشغيل خادم محلي على منفذ 5000
- إعداد endpoint للـ combat calculations
- اختبار الاتصال من Unity

### 2. واجهة القتال البسيطة
**الهدف:** إرسال تشكيلة من Unity واستقبال النتيجة
- قائمة وحدات للاختيار منها
- زر "هجوم" يتم حساب النتيجة
- عرض الخسائر المرسلة (من نظام `BloodCycleSystem.md`)

## المرحلة 4: الاختبار والتحسين (3-5 أيام)

### 1. اختبار الشامل
- اختبار التنقل بين المباني
- اختبار نظام القتال
- اختبار حفظ/تحميل البيانات

### 2. التحسينات البسيطة
- إصلاح الأخطاء
- تحسين الأداء
- إضافة رسائل خطأ/نجاح
